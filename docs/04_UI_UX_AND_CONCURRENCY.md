## 2. Покрытие требований к GUI (Неделя 9)

| Требование 9-й недели | Реализация в Fyne v2 (`internal/ui`) |
| :--- | :--- |
| **Окна (`Window`)** | Главное окно `fyne.Window` (`1200x760`), окна диалогов и аналитики. |
| **Кнопки (`Button`)** | Кнопки с иконками на панели инструментов (`widget.NewButtonWithIcon`), кнопки действий в карточке контакта (Primary, Danger, LowImportance). |
| **Поля ввода (`Entry`, `Select`, `Check`)** | Поле живого поиска с `OnChanged`, поля формы контакта (`FirstName`, `LastName`, `Phone`, `Email`, `Address`), выпадающий список групп (`widget.NewSelect`), чекбокс «В избранное» (`widget.NewCheck`). |
| **Таблицы / Списки (`List`, `Table`)** | Виртуализированный список контактов `widget.NewList` (плавно отрисовывает даже 10 000 записей) + таблица статистики и аудита `widget.NewTable`. |
| **Меню (`MainMenu`)** | Верхнее системное меню `fyne.NewMainMenu`: *Файл* (Импорт, Экспорт, Бэкап, Выход), *Контакты* (Создать, Избранные, Обновить), *Инструменты* (Импорт из REST API, Аудит базы, Переключить тему), *Справка* (О программе). |
| **Диалоговые окна (`Dialog`)** | Модальные диалоги: `dialog.ShowForm` (создание/редактирование), `dialog.ShowConfirm` (подтверждение удаления), `dialog.ShowError` (вывод ошибок валидации), `dialog.ShowInformation`, файловые диалоги. |
| **Обработка событий** | Колбэки `OnTapped`, `OnChanged` (живой поиск), `OnSelected` (выбор контакта или группы в списке). |
| **Обновление интерфейса** | Потокобезопасное обновление виджетов через `widget.Refresh()`, реактивные привязки данных и каналы состояния. |

## 3. Конкурентное программирование (Неделя 10)

Чтобы конкурентность в проекте была **не искусственной, а реально полезной и наглядной на защите**, реализуются **3 полноценных конкурентных механизма**:

### 3.1. Пул воркеров (`Worker Pool`) для пакетного импорта и валидации
Когда пользователь импортирует большой CSV/JSON или загружает пачку контактов из REST API:
1. Создается канал задач `jobs := make(chan domain.Contact, 100)` и канал результатов `results := make(chan ImportResult, 100)`.
2. Запускается $N = 4$ параллельных горутины (`go worker(id, jobs, results, &wg)`).
3. Каждая горутина параллельно очищает телефоны, валидирует поля, нормализует регистр ФИО и проверяет дубликаты.
4. Отдельная горутина-агрегатор ждет завершения через `sync.WaitGroup` и закрывает канал `results`.
5. Канал прогресса `progressChan` передает процент выполнения в UI, где плавно бежит `widget.NewProgressBar()`.

### 3.2. Фоновый планировщик автобэкапов на `select` и `time.Ticker`
При старте приложения запускается фоновая горутина `BackupScheduler`:
```go
func (s *BackupScheduler) Start(ctx context.Context) {
    ticker := time.NewTicker(s.interval)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            // Корректное завершение при закрытии окна приложения
            return
        case <-s.triggerNowChan:
            // Немедленный бэкап по кнопке пользователя
            _ = s.performBackup()
        case <-ticker.C:
            // Автоматический бэкап по расписанию
            _ = s.performBackup()
        }
    }
}
```
Это наглядно демонстрирует преподавателю владение `goroutines`, `channels`, мультиплексором `select` и `context.Context`.

### 3.3. Потокобезопасный In-Memory Кэш с `sync.RWMutex`
Для быстрого поиска по ID и проверки уникальности телефона без лишних обращений к диску используется структура `ContactCache`, защищенная `sync.RWMutex`:
* Читающие горутины берут разделяемую блокировку `mu.RLock() / mu.RUnlock()`.
* Модифицирующие операции берут эксклюзивную блокировку `mu.Lock() / mu.Unlock()`.

## 4. Сетевое взаимодействие и REST API (Неделя 11)

В пакете `internal/infrastructure/network` реализуются два сетевых сценария с использованием стандартного `net/http` и JSON:

1. **Импорт реалистичных контактов из внешнего REST API (`https://randomuser.me/api/?results=10&nat=us,gb,fr`):**
   * Нажатием одной кнопки *«🌐 Загрузить демо-контакты из API»* в панели инструментов приложение делает HTTP GET-запрос, десериализует сложный вложенный JSON-ответ сервера, преобразует его в структуры `domain.Contact` и сохраняет в БД.
   * Если интернет на защите отключен, предусмотрен **Graceful Fallback** (автоматическое переключение на встроенный локальный генератор реалистичных русскоязычных контактов), поэтому демонстрация на защите пройдет безупречно при любых условиях!
2. **Встроенный локальный REST API сервер (Бонусная фича для 100% баллов):**
   * Приложение может в фоновой горутине поднимать легкий локальный HTTP REST-сервер (например, на `http://localhost:8089/api/v1/contacts`), позволяя получать список контактов и статистику из браузера или через Postman/curl, а также опрашивать его собственным встроенным HTTP-клиентом!
