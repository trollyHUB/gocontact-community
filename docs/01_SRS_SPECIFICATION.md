# Техническое задание (SRS — Software Requirements Specification)
## Информационная система «Адресная книга» (GoContact Studio Community Edition)

**Версия документа:** 1.0  
**Статус:** Базовая спецификация релиза v0.1.0  
**Язык реализации:** Go (Golang) 1.27+  
**Тип приложения:** Кроссплатформенное настольное приложение с графическим интерфейсом (Desktop GUI)  

---

## 1. Введение и назначение системы

### 1.1. Цель проекта
Разработка современной, отказоустойчивой и производительной настольной информационной системы **«Адресная книга» (GoContact Studio Community Edition)** на языке программирования Go. Система предназначена для локального хранения (Local-First), категоризации, быстрого поиска, резервного копирования, пакетного импорта/экспорта и сетевого обогащения контактных данных.

### 1.2. Инженерные принципы и стандарты разработки
Проект спроектирован в строгом соответствии с передовыми мировыми практиками разработки на Go:
1. **Чистая архитектура (Clean Architecture):** Абсолютная изоляция доменного ядра (`internal/domain`) с нулевыми сторонними зависимостями от баз данных, GUI или фреймворков.
2. **Шаблон MVP (Model-View-Presenter):** Чёткое разделение ответственности между отображением (Fyne v2), бизнес-логикой презентера (`ContactPresenter`) и сервисами.
3. **Надёжная конкурентность:** Безопасное параллельное выполнение задач через `Worker Pool`, неблокирующие каналы, `select` с таймерами и контекстами отмены (`context.Context`), защита структур через `sync.RWMutex`.
4. **Промышленный уровень качества:** Высокое покрытие unit-тестами (Table-Driven Tests), детерминированные результаты и защита от утечек ресурсов (Goroutine/Memory Leaks).

## 2. Функциональные требования (Functional Requirements)

### FR-1. Управление контактами (CRUD)
* **FR-1.1. Создание контакта:** Пользователь может создать новый контакт со следующими атрибутами:
  * Уникальный идентификатор (`ID` / первичный ключ SQLite);
  * Имя (`FirstName`), Фамилия (`LastName`), Отчество (`MiddleName` — опционально);
  * Основной и дополнительный телефоны (`Phone`, `WorkPhone`) с классификацией типа номера (`Мобильный`, `Рабочий`, `Домашний`);
  * Электронная почта (`Email`);
  * Компания (`Company`) и Должность (`JobTitle`);
  * Физический адрес (`Street`, `City`, `Country`, `PostalCode` — вложенная структура `Address` через композицию);
  * День рождения (`Birthday`);
  * Группа/Категория (`GroupID`: *Семья*, *Работа*, *Друзья*, *VIP*, *Без группы*);
  * Теги (`Tags` — срез строк `[]string`);
  * Флаг «Избранное» (`IsFavorite` — `bool`);
  * Заметки (`Notes`);
  * URL или локальный путь к аватару (`AvatarPath`);
  * Метаданные аудита (`CreatedAt`, `UpdatedAt`).
* **FR-1.2. Просмотр карточки контакта:** Отображение полной информации о выбранном контакте в правой панели (паттерн *Master-Detail*).
* **FR-1.3. Редактирование контакта:** Изменение любых полей существующего контакта с мгновенной валидацией и сохранением в БД.
* **FR-1.4. Удаление контакта:** Удаление контакта с обязательным модальным окном подтверждения (`Confirm Dialog`).

### FR-2. Управление группами и категориями
* **FR-2.1.** Просмотр списка групп (предустановленных и пользовательских).
* **FR-2.2.** Создание, переименование и удаление групп контактов.
* **FR-2.3.** Подсчет количества контактов в каждой группе в реальном времени.

### FR-3. Поиск, фильтрация и сортировка
* **FR-3.1. Мгновенный полнотекстовый поиск (Live Search):** Поиск по подстроке в ФИО, номере телефона, email, компании и заметках по мере ввода текста.
* **FR-3.2. Комбинированная фильтрация:** Одновременная фильтрация по категории, статусу «Только избранные» и наличию заполненного email/телефона.
* **FR-3.3. Сортировка:** Возможность сортировки списка по алфавиту (А–Я, Я–А), названию компании и дате добавления.

### FR-4. Импорт и экспорт данных
* **FR-4.1. Паттерн «Стратегия»:** Единый интерфейс сериализации данных для поддержки расширяемых форматов хранения.
* **FR-4.2. Экспорт и импорт JSON:** Полная сериализация и десериализация адресной книги со всеми вложенными структурами и метаданными.
* **FR-4.3. Экспорт и импорт CSV:** Совместимость с табличными процессорами (Excel, LibreOffice Calc) и сервисами Google Contacts.
* **FR-4.4. Экспорт и импорт vCard (`.vcf`):** Поддержка формата визитных карточек RFC 2426 (vCard 3.0) для взаимодействия с мобильными устройствами (iOS / Android).

### FR-5. Сетевые возможности и локальный REST API
* **FR-5.1. Асинхронная загрузка аватаров по сети:** При отсутствии локального фото система асинхронно запрашивает аватар по инициалам или хешу через безопасный HTTP-клиент с таймаутами.
* **FR-5.2. Импорт демо-контактов из внешнего API:** Возможность пакетной загрузки контактов из открытых сервисов (`RandomUser API`) с офлайн-фоллбэком при отсутствии доступа в Интернет.
* **FR-5.3. Встроенный Local REST API сервер:** Предоставление локальных эндпоинтов HTTP (`:8089`):
  * `GET /api/v1/health` — проверка состояния сервиса;
  * `GET /api/v1/contacts` — получение списка контактов в формате JSON;
  * `GET /api/v1/stats` — агрегированная статистика адресной книги.

### FR-6. Пакетная конкурентная обработка (Goroutines & Channels)
* **FR-6.1. Фоновый импорт контактов (Worker Pool):** Пакетная загрузка больших объемов данных выполняется через пул из 4 горутин-воркеров, обновляя прогресс-бар (`ProgressBar`) без зависания GUI.
* **FR-6.2. Фоновый аудит контактов:** Параллельная проверка адресной книги на дубликаты номеров, корректность email-адресов и незаполненные поля с формированием интерактивного отчёта.
* **FR-6.3. Фоновый планировщик резервного копирования:** Периодический планировщик на базе `time.Ticker` и `select`, создающий резервные копии базы данных без прерывания пользовательской работы.

## 3. Нефункциональные требования (Non-Functional Requirements)

1. **Отзывчивость интерфейса (UI Responsiveness):** Время отклика интерфейса на действия пользователя — не более **16 мс (60 FPS)**. Все дисковые и сетевые операции выполняются в фоновых горутинах с возвратом в UI-поток через `fyne.Do()`.
2. **Надежность хранения данных (ACID):** Использование чистого Go-драйвера встраиваемой реляционной СУБД **SQLite** (`modernc.org/sqlite`) в режиме `PRAGMA journal_mode=WAL` с контролем целостности внешних ключей (`PRAGMA foreign_keys=ON`).
3. **Кроссплатформенность:** Полная совместимость исходного кода со средами Windows 10/11 (`windows/amd64`), macOS (`darwin/amd64`, `darwin/arm64`) и Linux (`linux/amd64`).
4. **Безопасность данных:** Строгое использование параметризованных SQL-запросов (`Prepared Statements` с плейсхолдерами `?`) для исключения SQL-инъекций.
5. **Покрытие тестами:** Ключевая бизнес-логика (валидация, CRUD-сервисы, импорт/экспорт, SQL-репозиторий) должна быть покрыта тестами на 100% пакетов.

## 4. Матрица модульной архитектуры и соответствия компонентов

| Компонент / Пакет | Назначение | Ключевые структуры и функции |
| :--- | :--- | :--- |
| **`internal/domain`** | Бизнес-ядро, сущности и валидация | `Contact`, `Address`, `Group`, `ValidationError`, нормализация телефонов РК/РФ. |
| **`internal/repository/interfaces`**| Контракты хранилища | Интерфейсы `ContactRepository` и `GroupRepository`. |
| **`internal/repository/sqlite`** | Реляционное хранилище SQLite | Драйвер `modernc.org/sqlite`, миграции схемы, WAL-режим, параметризованный поиск. |
| **`internal/repository/memory`** | Быстрый in-memory кэш | Кэш на базе `map[int64]*Contact` с защитой через `sync.RWMutex`. |
| **`internal/service`** | Бизнес-оркестрация и конкурентность | `ContactService`, `Worker Pool` импорта, фоновый планировщик `BackupScheduler`. |
| **`internal/infrastructure/fileio`** | Сериализация файлов | Экспорт и импорт в форматах JSON (`encoding/json`), CSV (`encoding/csv`), vCard 3.0. |
| **`internal/infrastructure/network`**| Сетевые адаптеры и API | `RandomUserClient` с офлайн-фоллбэком, встроенный HTTP-сервер `LocalAPIServer` `:8089`. |
| **`internal/ui`** | Графический интерфейс Fyne v2 | Архитектура MVP (`ContactPresenter`), Master-Detail интерфейс, адаптивная `StudioTheme`. |
| **`cmd/addressbook`** | Точка входа приложения | Инициализация зависимостей (DI), чтение конфигурации, запуск Fyne Event Loop. |
