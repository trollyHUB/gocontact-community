# Техническое задание (SRS — Software Requirements Specification)
## Информационная система «Адресная книга» (GoContact Studio)

**Версия документа:** 1.0  
**Статус:** Утверждено к разработке  
**Язык реализации:** Go (Golang) 1.27+  
**Тип приложения:** Кроссплатформенное настольное приложение с графическим интерфейсом (Desktop GUI)  

---

## 1. Введение и назначение системы

### 1.1. Цель проекта
Разработка современной, отказоустойчивой и масштабируемой настольной информационной системы **«Адресная книга» (GoContact Studio)** на языке программирования Go. Система предназначена для хранения, категоризации, быстрого поиска, резервного копирования, импорта/экспорта и сетевого обогащения контактных данных физических и юридических лиц.

### 1.2. Академическая и инженерная задача
Проект спроектирован таким образом, чтобы:
1. **На 100% закрыть все требования 15-недельного курса по языку Go** (от базового синтаксиса, структур и указателей до интерфейсов, горутин, каналов, REST API, SQL-базы данных, GUI и unit-тестирования).
2. **Соответствовать мировым индустриальным практикам (Best Practices)** разработки на Go: Clean Architecture, Standard Go Project Layout, Table-Driven Testing, Graceful Shutdown, потокобезопасность (Thread Safety) и отсутствие утечек горутин.

## 2. Функциональные требования (Functional Requirements)

### FR-1. Управление контактами (CRUD)
* **FR-1.1. Создание контакта:** Пользователь может создать новый контакт с полями:
  * Уникальный идентификатор (`ID` / `UUID`);
  * Имя (`FirstName`), Фамилия (`LastName`), Отчество (`MiddleName` — опционально);
  * Основной и дополнительный телефоны (`Phone`, `WorkPhone`) с классификацией типа номера (`Мобильный`, `Рабочий`, `Домашний`);
  * Электронная почта (`Email`);
  * Компания (`Company`) и Должность (`JobTitle`);
  * Физический адрес (`Street`, `City`, `Country`, `PostalCode` — вложенная структура `Address` через композицию);
  * День рождения (`Birthday`);
  * Группа/Категория (`GroupID`: *Семья*, *Работа*, *Друзья*, *VIP*, *Без группы*);
  * Теги (`Tags` — срез строк `[]string`);
  * Флаг «Избранное» (`IsFavorite` — `bool`);
  * Заметки (`Notes`);
  * URL или локальный путь к аватару (`AvatarPath`);
  * Метаданные времени (`CreatedAt`, `UpdatedAt`).
* **FR-1.2. Просмотр карточки контакта:** Отображение полной информации о выбранном контакте в правой панели (паттерн *Master-Detail*).
* **FR-1.3. Редактирование контакта:** Изменение любых полей существующего контакта с мгновенной валидацией и сохранением в БД.
* **FR-1.4. Удаление контакта:** Удаление контакта с обязательным диалоговым окном подтверждения (`Confirm Dialog`).

### FR-2. Управление группами и категориями
* **FR-2.1.** Просмотр списка групп (предустановленных и пользовательских).
* **FR-2.2.** Создание, переименование и удаление групп контактов.
* **FR-2.3.** Подсчет количества контактов в каждой группе в реальном времени.

### FR-3. Поиск, фильтрация и сортировка
* **FR-3.1. Мгновенный полнотекстовый поиск (Live Search):** Поиск по подстроке в ФИО, номере телефона, email, компании и заметках по мере ввода текста.
* **FR-3.2. Многокритериальная фильтрация:**
  * Фильтр по выбранной группе/категории;
  * Фильтр «Только избранные» (`IsFavorite == true`);
  * Фильтр по городу/стране.
* **FR-3.3. Сортировка:** По алфавиту (А–Я / Я–А), по дате добавления, по компании.

### FR-4. Импорт, экспорт и файловый обмен (JSON / CSV / vCard)
* **FR-4.1. Экспорт в JSON:** Полная выгрузка адресной книги (включая вложенные структуры и группы) для резервного копирования.
* **FR-4.2. Импорт из JSON:** Восстановление контактов из JSON-файла с разрешением дубликатов (пропуск или обновление).
* **FR-4.3. Экспорт и импорт CSV:** Совместимость с табличными процессорами (Excel, Google Sheets) и Google Contacts.
* **FR-4.4. Экспорт в vCard (`.vcf` — дополнительная фича):** Генерация стандартной электронной визитки для смартфонов (iOS / Android).

### FR-5. Сетевые возможности и REST API (HTTP-клиент)
* **FR-5.1. Автогенерация и загрузка аватаров по сети:** При отсутствии фото приложение асинхронно обращается к внешнему REST API (например, Gravatar / UI-Avatars / DiceBear API) для получения изображения по инициалам или хешу Email.
* **FR-5.2. Интеграция со справочным REST API:**
  * Обогащение данных по номеру телефона / городу или синхронизация/импорт демо-контактов из внешнего REST-сервиса (`JSONPlaceholder` / `RandomUser API`) для быстрой демонстрации работы с больших объемом данных на защите.

### FR-6. Пакетная конкурентная обработка (Goroutines & Channels)
* **FR-6.1. Фоновый импорт/экспорт:** При импорте больших файлов (1 000+ контактов) обработка выполняется в пуле воркеров (`Worker Pool` на горутинах), а прогресс передается через канал (`chan ProgressEvent`) в графический индикатор (`ProgressBar`) без блокировки окна.
* **FR-6.2. Фоновый аудит контактов (Health Check):** Параллельная проверка всей базы контактов на дубликаты номеров, битые email и незаполненные поля с формированием отчета.
* **FR-6.3. Фоновое автосохранение бэкапа:** Периодический воркер (`time.Ticker` + `select`), создающий резервный слепок базы в фоновом режиме.

## 3. Нефункциональные требования (Non-Functional Requirements)

1. **Отзывчивость интерфейса (UI Responsiveness):** Время отклика UI на действия пользователя не должно превышать **16 мс (60 FPS)**. Любые дисковые и сетевые операции длительностью > 50 мс выносятся в отдельные горутины.
2. **Надежность хранения (ACID):** Использование встраиваемой реляционной СУБД **SQLite** в режиме `WAL (Write-Ahead Logging)` с поддержкой внешних ключей (`FOREIGN KEY`) и транзакций.
3. **Кроссплатформенность:** Приложение должно компилироваться и работать на Windows 10/11, Linux и macOS без изменения исходного кода.
4. **Безопасность данных:** Защита от SQL-инъекций за счет строгого использования параметризованных запросов (`Prepared Statements` с плейсхолдерами `?`).
5. **Покрытие тестами:** Ключевая бизнес-логика (валидация, сервис контактов, парсеры CSV/JSON, SQL-репозиторий) должна быть покрыта unit-тестами не менее чем на **80%**.
